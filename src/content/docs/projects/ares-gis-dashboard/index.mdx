## Goal

Give a net control or command post one map that shows where ARES operators are, what incidents and tasks are open, and who is assigned to what, no matter which radio system each operator is reporting through. "Done" means a dashboard that keeps working when some feeds are down, tells you honestly which feeds are healthy, and lets a dispatcher assign an operator to a task in a few clicks.

## Constraints

- **Mixed sources:** operators report by APRS, Meshtastic mesh, DMR or a manual check-in, and one person may show up on more than one.
- **Degraded networks:** upstream feeds (FEMA, NWS, state traffic, ArcGIS) may be unreachable during an incident, so every feed reports its own status instead of failing silently.
- **Security:** protected routes always require authentication, and all credentials live in the host's secret settings, never in the repository.
- **Privacy:** sharing your own GPS position is opt-in, off by default, and expires automatically when your browser stops sending updates.

## Architecture

```text
APRS (aprs.fi API) ─┐
Meshtastic (MQTT) ──┤                     ┌─► Operators drawer (filter by source)
DMR (optional) ─────┼─► Fusion engine ────┼─► Map markers (styled by best source)
Manual check-ins ───┤   (merge by call    └─► Dispatch and assignment
Browser / serial GPS┘    sign or alias)

Incidents · Tasks · Assignments ─► local JSON store ─► Express API ─► Leaflet UI
NOAA · FEMA · FL511 · ArcGIS feeds ─► feed status ─► System diagnostics drawer
```

- **Fusion engine:** merges APRS, Meshtastic, DMR and manual records for the same operator, including Meshtastic nodes whose names contain a call sign, and shows a source count and badge on each merged marker.
- **Command layers:** searchable layer drawer with category accordions, show and hide toggles, and browsable layer records.
- **Workflows:** operators, incidents, tasks, check-ins and dispatch assignments, with a status board for manual check-ins.
- **Night operations:** a grayscale night base map, a detailed day base map, and a fallback when a base map provider is unavailable.
- **Diagnostics:** persistence, feed state, tracking provider health, live layer sync and laptop GPS status in one drawer.

## Configuration

Configuration is environment-driven. The repository ships an example file with placeholder values only.

- **Security:** basic authentication on, a non-default username and password set in the host dashboard, and a generated admin API token.
- **Tracking:** tracking on, with refresh and stale-position timers.
- **Providers:** APRS, Meshtastic and DMR are each off by default and are turned on only after their credentials and endpoints are configured.
- **GPS:** server-side serial GPS for local Windows use only. Cloud deployments leave it off and use the browser's "Connect GPS" button instead.

<Callout type="safety">
Operational settings such as tracked call sign lists, mesh channel settings and access credentials are deliberately left off this page.
</Callout>

## Build steps

1. `npm ci`
2. `npm run build:client`
3. `npm start`, then open the dashboard locally.
4. Optional: `npm run seed:data` for sample data.
5. For hosting, create a Render Blueprint from the repository, set the secret values Render asks for, and deploy. The health check path is `/healthz`.

## Safety notes

- This is a situational awareness tool, not a dispatch system of record. Follow the served agency's procedures.
- Position data is only as current as each source. Stale positions are marked, and a position should never be treated as confirmed without a radio check.
- Keep the dashboard behind authentication. Operator positions are sensitive during an incident.

## Lessons learned

- Fused tracking has to recalculate from the current raw operator records. Returning a cached operator view caused dispatch assignments to look like they had not saved.
- An auth layer that quietly leaves routes open when settings are missing is worse than no auth layer. The middleware now rejects unauthenticated requests even when the auth settings were omitted.
- Showing each feed's health on screen matters more than adding another feed.
