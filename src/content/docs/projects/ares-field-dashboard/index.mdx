## Goal

When an activation starts, every tool an ARES operator needs should be one tap away on the field laptop, and it should work with no internet. "Done" means one touch-friendly screen that launches the radio, Winlink, APRS, mesh, GPS, weather, ICS forms and documentation tools, shows which ones are installed and which are missing, and keeps the mission context (plan, PACE matrix, hardware staging and operator log) in one place.

## Constraints

- **Hardware:** Panasonic Toughbook CF-33 on Windows 11, used with gloves and in sunlight, so the interface is touch-first with light, dark and high-contrast modes.
- **Offline:** no cloud dependency, no telemetry, no account and no paid service. External web resources are labeled as links.
- **Safety:** the dashboard never transmits on amateur radio, never keys PTT, never schedules or bridges traffic, and never switches vehicle lighting on its own.
- **Non-destructive:** setup actions create missing folders and starter files only. They never delete or overwrite existing files.

## Architecture

```text
Electron main process ─► local JSON settings (Windows user profile)
        │                     │
        │                     └─► import / export backup
        ▼
React renderer (touch UI)
  ├─ Launcher catalog ─► checks each target: Ready · Missing · Link · System
  ├─ Mission Ops ─► mission packs · PACE matrix · hardware staging · operator log
  ├─ Field checklists ─► local progress
  └─ System status ─► COM / USB serial ports · battery · network · clock
```

The launcher catalog is grouped so field communications sit at the top and maintenance and recovery tools sit lower. Modules include ARES / Field Communications, Packet / APRS, Mesh / LoRa / AREDN, GPS / GNSS, Weather / Hazards, ICS Forms, TAK, Radio Programming, SDR / Monitoring, Network diagnostics, System Health, Storage Cleanup, Media / Recovery, and Vehicle Systems.

New default launchers merge into existing settings by a stable ID, so an update never wipes the operator's custom paths.

## Configuration

- **Launcher types:** program, folder, document, template folder, URL, Windows system command or settings URI, and explicit local command.
- **Settings editor:** every launcher path, folder, link and command can be changed in the app and is saved locally.
- **Field kit folders:** a one-click action builds the standard field kit folder tree (radio programming, Winlink, ICS forms, maps, manuals, mission packs, PACE plans, inventory, offline binder, logs, recovery and more) and adds CSV starters for the PACE matrix, hardware inventory, operator log and tactical call sign roster, only when they do not already exist.
- **Helper scripts (PowerShell):** a dashboard health audit, an offline software manual library builder, and a controlled installer for the field kit software.

## Build steps

1. `npm install`
2. `npm run dev` for development, or double-click `Launch Dashboard.cmd` to run it like a field app.
3. `npm run build` for a production build.
4. `npm run build:win` to produce the Windows installer.

## Safety notes

- The dashboard is a planning, launching and logging surface only. All radio traffic stays a direct operator action in the radio software itself.
- Vehicle lighting is reachable only through an explicit launcher that opens the [Vehicle Light Controller](/projects/vehicle-light-controller/), which keeps its own visible ALL OFF control.
- Any future action that writes to hardware should require confirmation and a local log entry.

## Lessons learned

- Showing Ready or Missing next to every launcher turns the dashboard into a readiness check. A missing tool is found at home, not at the incident.
- Merging new defaults by stable ID is what makes it safe to keep improving the catalog on a laptop that is already configured.
