## Goal

Give every project one public home where the parts, wiring, code and test results are written down in the same format, and where it is always clear what has and has not been tested. The site also serves as a portfolio of how I plan, build and document systems.

## Constraints

- **Budget:** $0. Free hosting, free tools, and no paid services without a decision first.
- **Privacy:** no home address, phone number, VIN, plate, permit numbers or parking locations. Photos have location data stripped. Scanner examples use synthetic IDs only. No employer confidential data and no unpublished emergency-communications details.
- **Honesty:** no invented metrics. Every page has a testing section that says what was not tested.
- **Consistency:** build projects follow the same 12-section template, and business case studies follow one case-study standard that keeps confirmed facts apart from anything not documented.

## Architecture

```text
MDX pages in GitHub ─► push to main ─► Cloudflare Pages build (astro build, Node 24) ─► static site on pages.dev
```

The site is fully static. Content lives in `src/content/docs/` as MDX files, and reusable components (header card, status badges, spec box, parts table, wiring table, callouts, changelog, gallery, before/after slider, download card and project grid) live in `src/components/`.

## How it was built with Claude

I wrote the site plan: the name, design tokens, menu, categories, status badges, page template and privacy rules. Claude built the site from that plan, checked the name and domain options, wrote the components and the first project pages, and turned my F-150 project document into the upfit overview and CanTrol output plan. Changes ship as pull requests that I review before they reach main.

## Configuration

- **Build command:** `npm run build`
- **Output directory:** `dist`
- **Environment:** `NODE_VERSION=24`
- **New project page:** copy `src/content/docs/projects/_template.mdx`, fill in the frontmatter, and set `project: true` so it appears in the project grid.

## Build steps

1. Write the site plan: name, design, menu, page template and privacy rules.
2. Scaffold Astro and Starlight, and add the design tokens and fonts.
3. Build the documentation components.
4. Publish the first project pages.
5. Connect the GitHub repository to Cloudflare Pages.
